目前的钉钉项目管理流程：
1. 策划按时填写项目版本、策划开始时间、美术验收时间、125-888-正式-提审时间。
2. 程序预估工期，拆解任务，填写预估时间。随着任务进行，填写实际时间和是否延期。
3. 参与的每个岗位 每日需提交日报。
4. 项目经理 需监督成员 手动补充进度、核对进度是否可靠，需定期整理 PPT 向主管汇报。
这个过程非常繁琐低效，耗费了大量时间。
我希望在与 钉钉项目管理表格有类似效果的前提下，能够加入角色进度自动化更新表格的功能。


优化方向：自动化展示进度看板、自动化更新项目推进情况、自动化进行 日报 和 周报 生成。
功能点：
1. 客户端页面：按 tab 切换以下页面，需要丝滑的动画过度。
  a. 总看板：展示每个角色本周工时、在进行中的项目版本。
  b. 任务列表：每个项目是一个条目树，任务列表是若干个条目树，每个拥有子条目的条目都可以折叠和展开。支持在每个条目下添加和删除子条目，也允许修改子条目的内容。
    ⅰ. 支持按负责人、按项目、按状态筛选任务列表。
    ⅱ. 每个条目至少包含：名称、负责人、任务状态、预估开始与结束时间、预估用时、子负责人、负责人备注。
    ⅲ. 子条目的逻辑含义是：父条目的分任务。因此。子条目继承父条目的负责人，当父条目任务状态为完成时，子条目也展示为已完成（计算时和展示上按照已完成展示，实际上可以保留自己的状态，为了便于误操作的快速回退）。
    ⅳ. 关于日期划分：必须安排 根条目的开始与结束时间。子条目可以根据 预估用时 自动计算出开始和结束时间。
    ⅴ. 子负责人先预留，他可能是真实的某个人，也可能是负责人按逻辑划分出来的 虚拟工作角色。
    ⅵ. 任务列表允许 web 端编辑，防止自动化有误。
    ⅶ. 关于 delay 的情形：如果一个任务有 delay，在子任务中插入 delay 条目。delay 条目需要明显与其他条目不同。
    ⅷ. 任务列表的更新：要考虑容灾性，允许回退。
  c. 日报与周报：汇报近期结束的项目进展情况，以及进行中项目的进度。
    ⅰ. 日报汇总 每个负责人当前版本及 最近 x 日完成的 上 m 个版本。
    ⅱ. 周报汇总 每个负责人当前版本及 最近 y 日完成的 上 n 个版本。
    ⅲ. 给出的变量数字支持配置。先做成服务端的 yaml 配置。
  d. 整体内容以 yaml 形式存储，需要每日备份；用户偏好以服务端 sqlite 形式存储。（比如 选中筛选方式、选中 tab 等等）
2. 自动化更新进度：
  a. 用户端：提供一个 skill。
    ⅰ. 帮助 负责人 拉取与自己相关的进行中的 项目数据。
    ⅱ. 引导 负责人 进行 版本任务拆解、时间预估。任务拆解完毕后，给出用户建议，待无误后，更新到 任务列表中。
    ⅲ. 当负责人 开始、完成 任务时，更新到任务列表中。
    ⅳ. 支持根据 负责人的 prompt ，将对应的任务更新到指定状态。
  b. 服务端：提供接口，支持用户 对任务列表的各种操作，该操作应当封装为 mcp 的形式。
  c. 服务端 使用 rust 进行开发。
3. 动画效果：条目的展开和收起、tab 之间的轮换 需要用高帧率的动画（类似于 MAC 的动画）
