# PM-DEV: 项目管理系统的领域语言

## 架构决策记录

- **钉钉替代策略**: 完全替代钉钉项目管理流程。预留接口空间供后续数据适配/推送。
- **日报生成策略**: 系统不直接调用 AI 生成日报。提供数据接口（md/yaml）+ 生成规范文档，由用户自行提交给 AI 生成。看板进度完全由程序化计算驱动。
- **权限模型**: 暂不实施成员级权限控制，留作后续迭代。
- **Skill 定位**: 用户端 Skill 在角色身份确认前加载（或直接在 CLAUDE.md 中提供）。工作目录缓存当前负责人信息。Skill 将引导负责人按角色划分任务、逐级拆解到最小粒度。
- **后端技术**: Rust Web 后端（Axum/Actix-web 等），单 exe 一键启动，不与现有服务耦合。本地调试后部署到堡垒机。
- **前端技术**: 传统 Web 页面（非 Rust 前端框架），作为在线看板。

## Skill 工作流（负责人流程）

1. Skill 在工作区加载，读取缓存的负责人名称。
2. 版本开始前，负责人通过 Skill 对当前版本的全部任务做逐级拆解，直到认为合适的粒度。
3. 拆解时按角色划分一级任务（如 CPP 侧 / 客户端侧 / CP 侧），每个一级任务继承负责人的名称。
4. 后续各子角色开发时：新建 Claude Code 会话 → 加载子角色身份 → Skill 在会话中拉取该角色的任务列表 → 引导更新进度。
5. 全局条目管理（跨角色调整）在 Web 页面手动进行。

## 任务状态

一个条目可取以下状态之一：

| 状态 | 含义 |
|------|------|
| 未开始 | 已创建但尚未动手 |
| 进行中 | 正在做 |
| 已完成 | 做完 |
| 已取消 | 不再需要 |
| 阻塞 | 因外部依赖无法推进 |

"待验收"不单独作为状态：A 的任务完成后，B 依赖于 A 的任务自然处于"未开始 → 进行中"的流转，反映了验收过程。

## Delay 条目

delay 条目在存储结构上与普通条目无异：
- **延期天数** = 预估天数（entry 的预估用时字段）
- **原因** = 负责人备注（entry 的备注字段）

触发方式：自动检测插入（实际 > 预估）或负责人手动标记。视觉上须与普通条目明显区分，以提示 PM 关注。

## 条目（Entry）约束

- **owner 必填**: 每条条目必须有负责人。
- **role 可选**: 子角色概念（角色级别的任务划分），由负责人选择是否填写。
- **owner 继承**: 子条目若不指定负责人，则继承父条目的负责人。根条目的负责人默认为工作区缓存的负责人名称。

## 核心概念

| 术语 | 定义 |
|------|------|
| **Product** | 正在开发的产品，如四川麻将、斗地主 |
| **Version** | 产品的某一迭代版本（如 v20.6.20260510）。一个 (产品 × 版本) 对应一棵条目树 |
| **Project** | = 某个产品的某个版本。项目管理针对一系列这样的项目进行可视化 |
| **Task (Entry)** | 任务以条目形式展示（类似 Excel 行/向量），各维度自动填充或 Web 手动编辑。每个任务可产生子任务 |
| **Entry** | 任务树的某一节点 |
| **Role** | 岗位：程序员、美术、策划等 |
| **Owner** | 每个项目的主要负责人。该项目中的大多数任务由负责人负责 |

## 关键规则

- **Owner 继承链**: 子条目继承父条目的负责人。当条目未指明负责人时，沿树向上追溯，最终以根条目的负责人为准。
- **日期计算**: 根条目记录预估开始时间。子条目只需提供预估用时，系统动态计算起止时间。父条目的预估结束时间由其子条目决定（详见时序模型）。
- **时序模型（当前）**: 串行模型。同一负责人下的任务串行执行。Child[n].start = Child[n-1].end。Parent.end = last_child.end。
- **时序模型（未来）**: 当工作区支持多角色并行机制时，可扩展为并行模型（不同角色的子条目可并行）。
- **有序性**: 同一父条目下的子条目按有序数组存储。插入/删除触发后续条目的时间重算。
- **完成传递**: 父条目标记为完成时，子条目在计算和展示上视为已完成，但保留自身实际状态以支持回退。

## 数据模型要求

1. **时间动态计算**: 根条目定开始时间，子条目仅需预估用时。
2. **有序子条目**: 数组存储，插入/删除触发重算。
3. **并发与回退**: 支持并发访问，数据回退，可迁移至其他系统。

## 存储格式决策

- **ID**: UUID v4（每个条目全局唯一，支持并发创建和未来迁移）
- **时间单位**: 预估用时以**小时**为记录单位，展示时按**天**换算（如 8h = 1d）
- **派生字段**: YAML 中仅存原始数据（estimated_hours, actual_hours），开始/结束时间由 server 动态计算，不落盘
- **树结构**: YAML 嵌套表示父子关系，children 为有序数组，顺序即执行顺序

## 回退与备份策略

**每日快照 + 操作日志**:
- `state.yaml` 始终为最新完整状态，每次写操作原子更新
- 同日内撤销：通过当日操作日志定位条目上一个状态并恢复
- 跨日回退：从 `backups/` 恢复某日快照
- 容量约束：整个 data/ 目录 ≤ 100MB

## 并发模型

- 写操作经 Rust server 串行化处理
- 客户端支持定时轮询或手动刷新获取最新状态
