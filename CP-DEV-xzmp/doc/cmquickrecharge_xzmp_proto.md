# 补充金币模块 设计文档（cmquickrecharge）

> **配置文件**：`cmquickrecharge_xzmp.jsonc`
> **CP服务脚本**：`cmquickrecharge_xzmp.ts`

## 功能概述

当玩家金币不足时（点击房间入口或本局游戏结束时），弹出补足金币界面，为玩家展示两种可购买礼包。

### 核心特性

- **多维度配置**：支持不同玩法、等级、房间配置、渠道的礼包配置
- **特惠礼包机制**：每个礼包携带一个特惠礼包，仅当玩家一段时间内充值金额高于判断值时触发
- **永久生效**：特惠礼包一经触发永久生效，但每个礼包下的特惠礼包仅能购买一次
- **等级限制**：若玩家特权等级高于当前触发礼包配置的 `levelNotShow`，则客户端不展示该礼包

## 实现细节

为玩家维护 **MySQL + Redis** 双存储的玩家状态数据，包含：

| 数据项 | 说明 |
|--------|------|
| 特惠礼包激活状态 | 记录已激活的特惠礼包 |
| 已购买状态 | 记录已购买的特惠礼包 |
| 流水信息 | 玩家最近一段时间的流水（滑动窗口，支持 7/30/90 天） |

## 通信行为

### 1. 进入游戏

**触发时机**：玩家进入游戏时

**行为**：客户端向 CP 服务脚本拉取配置信息

**响应**：返回配置信息及玩家状态数据（具体展示礼包的逻辑由客户端决定）

### 2. 充值行为

**触发时机**：进入 `onPayResult`

**行为**：
- 更新玩家最近的充值信息
- 通知客户端更新玩家状态数据

### 3. 购买特惠礼包

**触发时机**：客户端玩家申请购买特惠礼包

**行为**：向 CP 服务脚本鉴定礼包是否合法

**响应**：
| 结果 | 返回值 |
|------|--------|
| 合法 | `0` |
| 不合法 | 错误值 |
