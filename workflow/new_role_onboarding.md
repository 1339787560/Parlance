# 新建角色入手指南

## 第一步：确认角色名称和职责

询问用户：
- 角色名称是什么？（如：`Data-DEV`）
- 主要职责一句话？（如：负责数据分析管道维护）
- 使用什么技术栈？（如：Python, SQL, Airflow）
- 是活跃开发还是仅维护？

## 第二步：创建文件夹和 L0

1. 在 `A2AFile/` 下创建 `{Role}/` 目录
2. 在 `{Role}/` 下创建默认 `L0_Index.md`
3. 将 `A2AFile/CLAUDEForRole.md` 复制到 `{Role}/` 目录，将 `{Role}` 占位符替换为实际角色名
4. 在 `workflow/` 下创建 `{Role}_workflow.md`

### 默认 L0_Index.md 模板

```markdown
# L0 全局索引 - {Role}

> {角色描述}

---

## 核心职责

{一句话职责}

---

## 技术栈

| 技术 | 说明 |
|------|------|
| {语言} | {说明} |

---

## 工作区索引

| 工作区 | 路径 | 说明 |
|--------|------|------|

---

## 文档索引

| 文档 | 路径 | 说明 |
|------|------|------|
| 工作流 | [workflow/{Role}_workflow.md](../workflow/{Role}_workflow.md) | BDD 描述 — 启动后行为 |

---

## 协作角色

- {其他角色} — {协作说明}
```

### 默认 workflow 模板

```markdown
# {Role} 工作流

## 启动顺序

场景：新会话开始
前提 用户打开新的 {Role} 会话
当 第一条消息到达时
那么 角色静默执行以下启动流程：
- `curl GET /list` → 发现角色文件夹
- `curl GET /get?path=COMMON.md` → 公共规则
- `curl GET /get?path={Role}/L0_Index.md` → L0 索引
- 根据 L0 索引按需加载 L1/L2
- 全程不向用户报告启动步骤

## 待完善

场景：用户分配任务
前提 角色已完成启动
当 用户给出具体任务时
那么 待用户补充工作流细节
```

## 第三步：引导填充工作流

逐项询问用户：

1. **启动顺序** — 默认已提供，无需修改
2. **代码修改** — 该角色涉及什么文件类型？（.ts? .cpp? .py?）有无特殊编码规则？
3. **执行测试** — 如何运行测试？（命令是什么？有无 DEBUG 模式？）
4. **编译/构建** — 需要编译吗？用什么工具？
5. **设计新功能** — 有什么架构约束需要参考？

每确认一项，立即更新 L0 和 workflow 文档。

## 第四步：引导填充知识笔记

按优先级从高到低询问：

1. **工作区路径** — 代码仓库在哪？（多个路径列出）
2. **核心概念** — 该领域有哪些专有术语/缩写？（更新 Glossary）
3. **常用接口/API** — 需要调用的外部服务或模块接口
4. **已知陷阱** — 历史踩坑记录（可选，归入 L2）

写入对应 L1/L2 文档。

## 第五步：注册到 COMMON.md

1. 在 COMMON.md 角色定义表中添加新角色行
2. Role-Specific Test Execution 段不再维护（已在各角色 L0 中），跳过
3. 在现有角色的协作角色表中添加新角色（如适用）

## 完成标志

- `A2AFile/{Role}/L0_Index.md` — 职责、技术栈、工作区、协作关系完整
- `A2AFile/workflow/{Role}_workflow.md` — 启动、修改、测试、设计四个场景完整
- `A2AFile/COMMON.md` 角色定义表已更新
